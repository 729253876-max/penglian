## 3. MySQL 8 集成测试状态

新增的 `apps/api/test/mysql-identity.integration.test.ts` 使用真实 `mysql2` pool、
真实 `IdentityService`、真实 `MySqlIdentityRepository` 和仓库内
`migrations/001_identity.sql`，没有用 fake 代替数据库验收。它在获得资源后会串行
验证：

1. 生产迁移可在 MySQL 8 上重复执行；
2. 同一 OpenID 并发及重复 login 只产生一个用户和一条 identity binding；
3. 同一 refresh token 的两个并发请求恰有一个成功；
4. 第六台设备登录后最旧 session 被撤销；
5. 关闭并重建应用连接池后，未撤销 session 仍可 refresh；
6. 已撤销 session 在应用连接池重建后仍被拒绝。

安全边界：只有数据库名匹配 `photo_ai_b1_test` 或安全后缀，且
`MYSQL_INTEGRATION_ALLOW=1` 时才会连接。清理仅对已验证专用库内四张身份表执行
`DELETE`；不 `DROP DATABASE`，不打印 URL 或密码。危险数据库名会在连接、迁移和
清理之前拒绝。

本轮聚焦命令：

```text
npm.cmd test -- apps/api/test/mysql-identity.integration.test.ts --run --reporter=verbose
```

从正确 worktree 运行的真实结果为 exit 0，但 **1 个测试文件 skipped、6 个测试
skipped、0 个 MySQL 测试执行**；stderr 明确输出：

```text
[B1 MySQL integration] NOT ACCEPTED; skipped: MYSQL_INTEGRATION_URL is missing
```

因此 MySQL concurrency、迁移和应用连接池重建验收全部是 **NOT RUN / NOT ACCEPTED**，
不能把命令 exit 0 或 skipped 写成 PASS。

应用连接池关闭与重建不是 MySQL 实例重启；本轮没有验证数据库实例重启、故障
切换、备份或灾难恢复。readiness 的 `1500ms` 只是 mysql2 query inactivity
timeout，也不能据此声称端到端 readiness 在 1500ms 内必然返回。

另以无凭据、数据库名不符合安全前缀的本地占位 URL 和显式 allow 开关运行聚焦
文件，结果为 exit 1、0 tests，并在测试收集阶段返回
`MYSQL_INTEGRATION_REFUSED_UNSAFE_DATABASE`。该证据只证明危险库名 guard 在建连前
拒绝，不证明任何 MySQL 业务场景通过。

另有一次从规范项目主工作树而非本 Task worktree 误运行同一过滤命令，Vitest 因
找不到新文件以 exit 1 报告 `No test files found`。纠正运行目录后才取得上述明确
skip 证据；这次失败不代表 MySQL 被执行。
