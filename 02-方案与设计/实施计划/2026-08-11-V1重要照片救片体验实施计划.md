# V1 重要照片救片体验 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将阶段 A 的四工具首页改造成“重要照片救片”单一场景入口，并改进同图比较、真实精修信息折叠和安全的实验事件口径，同时继续只使用示例资产。

**Architecture:** 保持原生微信小程序和现有页面路由，不引入 UI 框架。场景映射、精修事件摘要和实验事件验证分别放入小型纯 TypeScript 服务；页面只管理交互状态。默认事件 sink 为 no-op，未经后续授权不向微信、API 或第三方发送数据。

**Tech Stack:** 原生微信小程序 WXML/WXSS/TypeScript、Vitest 3、`@photo-ai/contracts`、现有运行时编译脚本。

## Global Constraints

- 首屏只传播“重要照片/旅行人像救片”，主文案为“这张重要照片，还能救得更好。”
- 可信副标题必须包含“尽量保留本人、姿势和构图，先看预览，满意再解锁”的含义。
- V1 四项能力继续保留；当前只有人像精修示例纵向切片可操作，其余能力必须准确显示尚未接入，不得伪造可用上传或结果。
- 本计划只使用现有 `demo-before.svg` 与 `demo-after.svg`，必须标记为“示例”，不得称为真实用户案例或真实供应商结果。
- AI 精修实况继续只显示真实服务端事件；允许折叠展示，不得用客户端计时器新增虚构步骤。
- 不加入真实上传、真实供应商、支付、价格、积分、广告、分享奖励、审美档案或投放代码。
- 埋点默认 no-op；事件字段禁止包含图片、图片路径/URL、任务 ID、OpenID、会话令牌、手机号、自由文本和密钥。
- B1-ENV 仍为 NOT RUN；本地界面通过不等于三系统、真实身份、真实图片或发布通过。
- 页面必须保持加载、禁用、成功、失败、减少动态和无障碍语义；使用当前视觉系统，不做无关重构。
- `build:wechat` 会在 `miniprogram` 原位生成同名 `.js`；所有 `.ts` 与生成的 `.js` 必须同次提交，`.js` 不得手工编辑。
- 所有行为变更使用 TDD；每个任务独立提交；不得提交主工作区 `05-输出与交付` 的未跟踪文件。

```ts
Page({
  data: { comparePercent: 50, showDetails: false },
  setComparison(event: { detail: { value: number } }) {
    const comparePercent = Math.max(0, Math.min(100, Number(event.detail.value)));
    this.setData({ comparePercent });
  },
  toggleDetails() {
    this.setData({ showDetails: !this.data.showDetails });
  },
  adjustAgain() {
    wx.redirectTo({ url: "/pages/plan/index?scenario=travel-portrait" });
  }
});
```
