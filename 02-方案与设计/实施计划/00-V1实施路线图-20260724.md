# 修图 AI 小程序 V1 实施路线图

> 日期：2026-07-24  
> 需求基线：`01-需求与目标/修图AI小程序-PRD-v02-20260724.md`  
> 设计基线：`02-方案与设计/修图AI小程序-V1产品增长与AI精修实况设计-v01-20260724.md`

## 1. 拆分原则

V1 包含小程序、任务编排、供应商适配、AI 精修实况、支付账本、审美档案、增长归因、后台和隐私治理。它们不能放进一个实施计划同时开发。每个阶段必须交付一个可以独立运行、测试和评审的结果。

## 2. 推荐技术基线

- 客户端：原生微信小程序，TypeScript、WXML、WXSS。
- 服务端：Node.js `v24.18.0 LTS`、TypeScript、Fastify。
- 包管理：npm workspaces；Windows 使用 `npm.cmd`。
- 契约：Zod schema + TypeScript 推导类型。
- 测试：Vitest；API 使用 Fastify `inject`；小程序使用微信开发者工具自动化。
- 持久化：正式阶段使用 MySQL、Redis 和对象存储；第一阶段使用仓储接口和内存实现打通纵向切片。
- 后台：React + TypeScript，放到增长与运营阶段实施。
- 供应商：统一 `ImageProvider` 适配接口；第一阶段只使用确定性模拟供应商。

该技术基线优先满足国内部署、微信支付、异步图片任务和供应商可替换性。正式持久化与部署拓扑在第二阶段技术设计中冻结。

## 3. 阶段

### 阶段 A：基础与 AI 精修实况纵向切片

交付：

- npm monorepo。
- 覆盖四类 V1 工具的共享任务、事件和错误契约；老照片修复参数单独记录上色请求与显式确认。
- 任务状态机。
- AI 精修实况真实性过滤。
- 模拟供应商和任务编排。
- Fastify API。
- 原生小程序首页、参数确认、实况和预览页面。
- 自动化测试与微信开发者工具最小验证。

完成定义：

用户可以使用模拟图片资产创建人像精修任务，在小程序看到真实结构化事件逐条出现，并进入水印预览页；非法状态迁移和伪造事件被测试拒绝。

详细计划：

`2026-07-24-V1基础与AI精修实况纵向切片实施计划.md`

### 阶段 B：真实上传、审核、供应商与质量闭环

交付：

- 微信登录和授权记录。
- 上传会话、签名上传和对象存储。
- 图片审核。
- 四类工具统一参数；老照片修复专属参数包括是否请求上色及是否完成显式确认。
- 供应商适配和主备路由。
- 身份与非目标区域质量检查。
- 失败恢复、删除和数据保留。

进入条件：

- 阶段 A 通过。
- 供应商专项任务提供候选能力和测试账号。
- 数据保留与部署地域完成合规确认。

### 阶段 C：预览权益、积分、报价、支付与交付

交付：

- 免费预览权益。
- 激励视频权益。
- 积分批次与统一账本。
- 报价快照和预览抵扣。
- 一次微信支付。
- 高清交付、报告和退款。

进入条件：

- 阶段 B 至少有一个真实供应商链路稳定。
- 输出规格、综合成本和候选商品结构可以配置。

### 阶段 D：个人审美档案

交付：

- 单独授权。
- 可解释偏好。
- 反馈、收藏和解锁学习。
- 单次禁用、暂停、修改和清除。
- 权重配置和审计。

进入条件：

- 高质量结果和用户反馈数据稳定。
- 阶段 C 可以识别真实解锁与复购信号。

### 阶段 E：精准增长

交付：

- 场景化直达页。
- 分享卡和隐私选择。
- 渠道、活动和创作者归因。
- 邀请与奖励账本。
- CPS 数据和防刷。
- 冷启动实验看板。

进入条件：

- 阶段 C 的高清解锁和退款闭环稳定。
- 真实案例获得用户授权。

### 阶段 F：后台、运营、合规与灰度发布

交付：

- 工具、价格、权益、路由、文案和实验配置。
- 用户、任务、订单、退款、奖励和申诉管理。
- 成本、质量、漏斗和渠道看板。
- 审计、告警、删除回执和灾备。
- 微信真机、灰度、回滚和发布清单。

进入条件：

- A 至 E 的领域接口稳定。

## 4. 阶段门槛

任何阶段不得绕过：

- 真实事件可追溯。
- 任务与资金幂等。
- 用户图片最小化访问。
- 价格、权益和供应商配置化。
- 自动化测试通过。
- 实际运行或真机验证。
- 对应阶段的复盘和 HANDOFF 同步。
