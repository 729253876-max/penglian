# PR 合并前质量门禁 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 Draft PR #1 增加最小权限、可追溯、可回滚的 GitHub Actions 质量门禁，并在转为 Ready 前证明“完整文字修复过程”只来自实际事件和真实证据。

**Architecture:** 在现有 npm workspace 中新增一个无运行时依赖的 CI 契约测试包，用文本级白名单约束工作流的触发器、权限、Action 固定 SHA、runner、运行目录、门禁命令及禁止项；随后新增单一 Windows GitHub Actions 工作流复现五项本地门禁。CI 全绿后，独立复审者以 `master...PR head` 的完整差异为对象建立真实性证据矩阵；任何缺失、冲突、中断或未解决的 Critical/Important 都保持 Draft 和 fail-closed。

**Tech Stack:** GitHub Actions、Windows hosted runner、PowerShell、Node.js 24、npm 11、TypeScript 5.9、Vitest 3、现有原生微信小程序构建链。

## Global Constraints

- 本计划只实施 PR 合并前质量门禁，不重做已完成的 Tasks 1–9，不扩展产品功能。
- `pull_request` 仅在目标为 `master` 时自动触发，并允许 `workflow_dispatch`；禁止 `pull_request_target`。
- 工作流顶层权限只能是 `contents: read`；不得读取 GitHub Secrets，不得授予写仓库、发布、部署或云资源权限。
- 使用 GitHub 托管 `windows-latest`；Node.js 主版本固定为 `24`。
- `actions/checkout` 固定为 `3d3c42e5aac5ba805825da76410c181273ba90b1`（官方仓库 v7.0.1 release commit，MIT）。
- `actions/setup-node` 固定为 `7c2c68d20d402ed6a201ada70a81341941093140`（官方仓库 6.5.0 line commit，MIT）；实施前只读复核该 SHA 仍可访问、`action.yml` 指向已提交的 `dist`，不得改用浮动 tag。
- CI 中依赖只能在 `04-源文件与代码` 使用 `npm.cmd ci --ignore-scripts` 安装，并以 `04-源文件与代码/package-lock.json` 为缓存依据；CI 禁止执行依赖安装脚本或使用会改写 lockfile 的安装方式。新增本地 workspace 时只允许用 `npm.cmd install --package-lock-only --ignore-scripts --offline` 更新锁文件元数据，并人工核对差异。
- 五项门禁必须按顺序完整执行：`npm.cmd run typecheck`、`npm.cmd test -- --run`、`npm.cmd run verify:miniprogram-runtime`、`npm.cmd run build:wechat -w @photo-ai/miniprogram`、`git diff --check origin/master...HEAD`；最后一项必须检查已提交的完整 PR 差异，禁止退化为只检查干净工作区的无范围命令。
- Vitest 必须无文件筛选运行全量测试；现有关于真实事件、证据来源、事件顺序、失败码、一次重试、无预览和 fail-closed 的测试必须是阻断项。
- “完整文字修复过程”只能由服务端实际持久化的公开事件、用户选择、provider 处理回执和项目质量门禁证据生成；不得使用定时器、固定脚本、补写步骤或隐藏推理制造业务事件。
- `PREVIEW_PROVIDER_FAILED` 的终止证据只能是 `SYSTEM_CHECK`；`FIDELITY_GATE_FAILED` 的终止证据只能是 `QUALITY_GATE`；`PORTRAIT_NOT_SUITABLE` 和 `ASSET_NOT_APPROVED` 继续是创建前拒绝，不得伪装为 `TASK_FAILED`。
- 13 项 MySQL integration 和 1 项对象存储环境条件测试继续标记为 `NOT ACCEPTED`；CI 的 skipped 不是实际 MySQL/COS 验收通过。
- 不连接真实 MySQL、COS、STS 或模型服务，不上传用户照片、提示词或项目上下文，不部署、不发布、不迁移数据库、不执行付费调用。
- 不自动合并、不强推、不删除 worktree 或分支；工作流提交可以通过普通 `git revert` 回滚。
- Draft 转 Ready 是单独的 GitHub 状态写操作，必须在全部证据齐备后再次取得用户明确确认；转 Ready 不等于获准合并。

- [ ] **Step 4: 实现无依赖、稳定错误码的最小检查器**

实现先移除空行和纯注释，再检查完整 40 位 SHA、唯一允许的 Actions、精确命令数组与顺序。禁止通过执行 YAML、shell 或 workflow 内容来验证。

```ts
export type WorkflowContractCode =
  | "FORBIDDEN_TRIGGER" | "MISSING_TRIGGER" | "EXCESS_PERMISSION"
  | "FLOATING_ACTION" | "UNAPPROVED_ACTION" | "WRONG_RUNNER"
  | "WRONG_NODE" | "WRONG_CACHE_PATH" | "WRONG_CHECKOUT" | "WRONG_WORKDIR"
  | "MISSING_GATE" | "GATE_ORDER" | "FILTERED_TESTS"
  | "FORBIDDEN_SECRET" | "FORBIDDEN_REMOTE_OPERATION";

export interface WorkflowContractError {
  code: WorkflowContractCode;
  message: string;
}

const REQUIRED_RUNS = [
  "npm.cmd ci --ignore-scripts",
  "npm.cmd run typecheck",
  "npm.cmd test -- --run",
  "npm.cmd run verify:miniprogram-runtime",
  "npm.cmd run build:wechat -w @photo-ai/miniprogram",
  "git diff --check origin/master...HEAD"
] as const;

const ALLOWED_ACTIONS = new Set([
  "actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1",
  "actions/setup-node@7c2c68d20d402ed6a201ada70a81341941093140"
]);

const add = (
  errors: WorkflowContractError[],
  condition: boolean,
  code: WorkflowContractCode,
  message: string
) => {
  if (condition) errors.push({ code, message });
};

export function validateWorkflowContract(source: string): WorkflowContractError[] {
  const text = source.replace(/\r\n/g, "\n");
  const errors: WorkflowContractError[] = [];
  add(errors, /(^|\n)\s*pull_request_target\s*:/.test(text), "FORBIDDEN_TRIGGER", "pull_request_target is forbidden");
  add(errors, !/(^|\n)  pull_request:\n    branches:\n      - master\n/.test(text) || !/(^|\n)  workflow_dispatch:\s*\n/.test(text), "MISSING_TRIGGER", "master pull_request and workflow_dispatch are required");

  const permissions = text.match(/(^|\n)permissions:\n((?:  [^\n]+\n)+)/)?.[2].trim();
  add(errors, permissions !== "contents: read", "EXCESS_PERMISSION", "only contents: read is allowed");
  add(errors, !/(^|\n)    runs-on: windows-latest\n/.test(text), "WRONG_RUNNER", "windows-latest is required");
  add(errors, !/(^|\n)          node-version: 24\n/.test(text), "WRONG_NODE", "Node.js 24 is required");
  add(errors, !/(^|\n)          cache-dependency-path: 04-源文件与代码\/package-lock\.json\n/.test(text), "WRONG_CACHE_PATH", "the project lockfile must key npm cache");

  const uses = [...text.matchAll(/^\s+uses:\s*(\S+)\s*$/gm)].map((match) => match[1]);
  add(errors, uses.some((item) => !/@[0-9a-f]{40}$/.test(item)), "FLOATING_ACTION", "every action must use a full commit SHA");
  add(errors, uses.length !== 2 || uses.some((item) => !ALLOWED_ACTIONS.has(item)), "UNAPPROVED_ACTION", "only the two reviewed action commits are allowed");

  const runs = [...text.matchAll(/^\s+run:\s+(?!\|)(.+?)\s*$/gm)].map((match) => match[1]);
  add(errors, REQUIRED_RUNS.some((command) => !runs.includes(command)), "MISSING_GATE", "all six install/gate commands are required");
  add(errors, JSON.stringify(runs.filter((run) => REQUIRED_RUNS.includes(run as typeof REQUIRED_RUNS[number]))) !== JSON.stringify(REQUIRED_RUNS), "GATE_ORDER", "install and five gates must stay in order");
  add(errors, runs.some((run) => run.startsWith("npm.cmd test") && run !== "npm.cmd test -- --run"), "FILTERED_TESTS", "Vitest must run without file or test filters");

  for (const command of REQUIRED_RUNS) {
    const expectedDirectory = command === "git diff --check" ? "." : "04-源文件与代码";
    const escaped = command.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
    add(errors, !new RegExp(`run: ${escaped}\\n\\s+working-directory: ${expectedDirectory.replace(".", "\\.")}\\n`).test(text), "WRONG_WORKDIR", `${command} has the wrong working directory`);
  }

  add(errors, /\$\{\{\s*secrets\.|(^|\n)\s+(MYSQL_INTEGRATION_URL|COS_SECRET|STS_SECRET|MODEL_API_KEY)\s*:/m.test(text), "FORBIDDEN_SECRET", "secrets and real-service credential variables are forbidden");
  add(errors, /(^|\n)\s+run:\s+.*\b(deploy|publish|migrate|curl|Invoke-WebRequest|git\s+push)\b/im.test(text), "FORBIDDEN_REMOTE_OPERATION", "deployment, download and remote-write commands are forbidden");
  return errors;
}
```

每个错误码至少提供一个变异测试。日志可以显示字符串 `MYSQL_INTEGRATION_URL is intentionally absent`，但禁止定义该变量或任何 COS/STS/model credential；禁止项还包括 deploy、publish、migration、`curl`、`Invoke-WebRequest` 和远程写命令。

### Task 4: 对完整 PR 差异执行独立真实性复审
