# B3 供应商适配与主备路由 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把阶段 A 的同步模拟供应商调用改为持久化异步编排，建立四工具统一供应商端口、契约测试、主备路由、幂等和删除接口；真实供应商适配严格受供应商证据门禁约束。

**Architecture:** API 只在 MySQL 事务中创建任务、首事件和 `RUN_PROVIDER` 作业；Worker 调用 `ImageProvider` 端口。`ProviderRouter` 基于工具能力、健康状态和一次主备切换选择适配器，所有供应商调用以平台幂等键和 `provider_runs` 记录保护。没有真实供应商资料时只实现并验收中立内核和模拟适配器，不编造通用 HTTP 适配器。

**Tech Stack:** TypeScript、Node.js、Fastify、Zod、MySQL 8、Vitest、B2 MySQL 租约 Worker。

## Global Constraints

- V1 工具固定为人像精修、画质增强、路人/杂物消除、老照片修复。
- 老照片上色仅在 `colorizationRequested=true` 且 `colorizationConfirmed=true` 时传给供应商。
- 小程序不得直接调用供应商或接触供应商密钥。
- HTTP 请求生命周期不得等待供应商处理完成；受理成功返回 `202` 和服务端任务状态。
- 任务状态、首事件和作业必须同一事务提交；副作用必须幂等。
- 供应商未定不允许声称真实质量、成本、时延、收费、删除或主备切换已验收。
- 真实适配必须先取得供应商名称、接口文档、测试账号、计费规则、超时/失败收费规则和书面删除条款。
- 供应商重试次数、切备条件和收费处理只能由真实证据冻结，不能在中立内核硬编码。
- 任何真实供应商账号、密钥、上传、调用、对外申请或费用动作必须先征求用户同意。

await transaction(async (tx) => {
