# B4 质量、恢复、删除与数据保留 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在异步任务链路上实现可验证的质量检查、有限重试、Worker 崩溃恢复、数据生命周期、用户删除/注销清理和国内运行保障。

**Architecture:** 质量检查通过独立 `QualityInspector` 端口运行并产生结构化结果；编排器用 MySQL 作业和幂等键执行有限重试。`DataLifecycleService` 根据资产到期时间和删除请求创建幂等清理作业，立即关闭访问、24 小时内清理活跃数据，并记录供应商删除与告警。监控使用腾讯云可承载的结构化日志和指标端口。

**Tech Stack:** TypeScript、Node.js、Fastify、Zod、MySQL 8、Vitest、B2 Worker/B3 TaskOrchestrator、腾讯云日志与监控适配接口。

## Global Constraints

- 只有成功生成可查看水印预览后才允许未来权益模块扣减；本阶段不实现支付或积分账本。
- 质量失败只允许同任务有限重试，且必须复用任务身份、事件序号和权益幂等键。
- 原图 7 天、低清水印预览 7 天、付费结果 30 天。
- 用户主动删除后立即隐藏并禁止访问；业务索引与 COS 活跃对象 24 小时内删除。
- 备份最长 30 天自然淘汰，期间不得恢复到线上。
- 注销立即撤销全部会话、隐藏账号和图片、停止未开始任务；活跃用户数据 24 小时删除或不可逆匿名化。
- 供应商删除必须立即请求；失败持续重试并告警，不得静默完成。
- 日志和指标不得包含图片 URL、令牌、密钥、OpenID、原图、完整审核标签或供应商原始响应。
- V1 使用腾讯云结构化日志、指标、告警和操作审计，不引入境外 Sentry 等运行时 SaaS。
- 真实供应商质量阈值和重试收费规则只有 B3 证据齐全后才能冻结。
