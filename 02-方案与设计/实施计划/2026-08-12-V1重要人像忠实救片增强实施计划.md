# V1 重要人像忠实救片增强 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将已审核的真实上传资产接入“重要人像忠实救片”产品闭环，提供自然/清晰两档方案、完整且可恢复的文字修复实况、独立质量拒绝和一次有限重试，同时保持模型可替换且不宣称真实修图质量已通过。

**Architecture:** 沿用 TypeScript、Fastify、原生微信小程序和现有任务状态机。新增资产授权读取、诊断、方案、候选处理、质量门禁和修复日志六个窄接口；供应商只返回候选结果与处理回执，项目质量门禁独立决定是否生成预览。第一阶段使用确定性实现和测试替身，不下载模型、不调用真实供应商；MySQL 任务持久化、真实 Worker 和供应商路由仍由既有 B3/B4 计划承担。

**Tech Stack:** TypeScript 5.9、Fastify 5、Zod 4、MySQL 8 资产读取、原生微信小程序、Vitest 3、现有 COS/STS 上传链路。

## Global Constraints

- 第一切片只开放 `PORTRAIT_RETOUCH`；老照片修复、物体消除和泛画质增强继续显示为未开放。
- 上传资产必须属于当前用户、上传会话状态为 `APPROVED`、资产类型为 `NORMALIZED`；不得只信任前端传入 UUID。
- “自然救片”是默认推荐；“清晰救片”只能在相同忠实边界内提高细节，不引入换脸、瘦脸、五官重塑、妆容生成或背景替换。
- 完整文字修复实况是 P0；只展示真实结构化事件、用户选择、供应商处理回执和项目质量检查，不展示隐藏推理，不补写未发生步骤。
- `evidenceSource=PROVIDER_RECEIPT` 的事件不得是 `QUALITY_CHECK_PASSED`、`QUALITY_CHECK_FAILED` 或 `PREVIEW_READY`；最终放行只能由项目质量门禁产生。
- 质量失败最多真实重试一次；第二次仍失败时不得下发候选预览，并返回 `FIDELITY_GATE_FAILED` 与不扣权益文案。
- 第一阶段只证明产品闭环和拒绝机制；不得宣称真实模型质量、贡献毛利、真实时延或生产发布通过。
- 不下载、克隆、安装或执行第三方仓库与模型；不调用境外 API；不上传真实用户照片到新服务。
- 不训练自有模型；参数和阈值校准属于后续真实 PoC，不属于本计划实现。
- 当前任务仓储仍为进程内实现；页面离开后可恢复，API 进程重启后不可恢复。不得把本计划写成 B3 MySQL 任务持久化或 Worker 验收通过。
- 所有行为变更使用 TDD；每个任务独立提交；TypeScript 生成的微信 `.js` 必须与对应 `.ts` 同次提交。
- 不提交 `05-输出与交付/HANDOFF-v03.7-用户修改快照-20260811.md` 和 `05-输出与交付/新线程交接-B1代码门禁完成-v01-20260811.md`。
